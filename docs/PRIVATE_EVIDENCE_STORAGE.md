# Private evidence storage

TechSubbies evidence files are private application data. They must not be stored
as public URLs or embedded directly in engineer profile JSON.

## Runtime modes

### Development

`EVIDENCE_STORAGE_PROVIDER=local` stores files under
`backend/data/private-evidence` by default (or `EVIDENCE_LOCAL_ROOT`). Files are
created with owner-only filesystem permissions where supported and are served
only through authenticated `/api/evidence/:id/content` requests.

### Production

Production startup requires:

- `EVIDENCE_STORAGE_PROVIDER=s3`
- `EVIDENCE_S3_BUCKET`
- `AWS_REGION`
- `AWS_ACCESS_KEY_ID`
- `AWS_SECRET_ACCESS_KEY`
- optional `AWS_SESSION_TOKEN` for temporary credentials

The application signs S3 REST requests with AWS Signature Version 4. Object
keys are generated by the backend and never returned by the public API.

## Required bucket controls

Before production deployment:

1. Enable S3 Block Public Access for the account/bucket.
2. Disable ACL-based public access and do not configure a public website.
3. Enable default server-side encryption (SSE-S3 or SSE-KMS).
4. Restrict the application IAM principal to the evidence bucket and the
   `evidence/*` prefix only.
5. Allow only `GetObject`, `PutObject` and the minimum lifecycle/delete actions
   the application actually requires.
6. Enable CloudTrail data events or equivalent object-access logging for the
   bucket in addition to the application audit table.
7. Configure retention/lifecycle rules only after the privacy and evidence
   retention policy is agreed.

## Application access policy

Evidence is private by default:

- the engineer who owns an evidence item may upload and read it;
- an Admin may read it for trust/verification operations;
- another engineer, company or resourcing company cannot read it;
- object keys and filesystem paths are never returned to clients;
- successful and denied access attempts are written to
  `evidence_access_events` with the actor and request ID;
- download responses use `Cache-Control: private, no-store`.

Company/resourcing visibility is deliberately not implemented in this slice.
That belongs to the certificate verification and evidence visibility-control
work item, where access can be granted explicitly rather than making evidence
public by default.
